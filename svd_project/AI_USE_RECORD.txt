Project development record
MATH 300 video SVD project
Updated November 20, 2026

I completed this project using resources provided in class and cited online references. No AI assistance was used.

Project approach

I used the course material on QR, matrix decompositions, reduced SVD, and image
compression to study how a video can be represented by a small set of basis
images and a set of weights for each frame. The cited research paper provides
the mathematical background for the incremental column-update method, and the
software references explain the Python tools used to process the data.

The project reads a video, converts frames to grayscale, resizes them, and
stacks the frame vectors into a matrix. It compares batch SVD with an
incremental column-update SVD. The incremental implementation uses residual
QR, a small SVD, QR reorthogonalization, and rank truncation at initialization
and after every update. The update routine is reusable across frame blocks.

The experiments compare ranks 1, 5, and 20 using reconstruction errors,
factor-storage estimates, and frame images. The script exports the plots and
rank_comparison.csv so the numerical results can be checked alongside the
figures.

Data and checked results

Source video: 20261113_222244000_iOS.MOV, provided through my OneDrive.
Actual decoded count: 184 frames. The container metadata lists 194, so the
metadata count was not used as the analyzed count. Every other decoded frame
gave 92 grayscale frames, resized to width 54 and height 96 pixels. Y therefore
has shape (5184, 92). Block size is 10. The last block contains two frames.

The known test matrix has singular values 5, 5, 2, 0. Additional checks covered
16 block-size/rank combinations and a case that detects delayed truncation.
The latest automated full-video run gave approximate untruncated relative
reconstruction error 8.051e-15, relative spectrum error 8.844e-16, and left
orthogonality error 1.559e-14. Last digits can vary with floating-point execution.

Rank comparisons and storage values are saved in rank_comparison.csv.
The image comparisons use sampled frame 47 of 92, with shared display limits
0 to 255. Errors were measured on floating-point reconstructions before display
clipping. The implementation preloads Y. Factor-storage estimates are not
measurements of streaming peak memory or comparisons against the encoded MOV.

Report and project package

The report explains shared basis images and per-frame weights, distinguishes
retained rank from block size and frame count, and describes projection,
residual QR, the small SVD, the second QR correction, and truncation in a
numbered sequence. The November 20 revision clarified the explanations and
data introduction without changing the analysis code or numerical results.
The PDF, LaTeX source, and Overleaf review bundle were updated together.

The project is organized under svd_project in hakimwsu/wsu_math300. The package
contains the current report, accompanying figures and results, tested code,
dependencies, prepared frame data, source mappings, and run instructions.
The matching report PDF is rebuilt from the supplied LaTeX source. Older SVD
report drafts are not included in this project folder.

Portable reproduction

With no video path, practice.py loads data/prepared_frames.npy using
allow_pickle=False. With a video path as the first command-line argument, it
uses the same grayscale, resizing, and temporal-sampling pipeline. Closing the
video iterator is conditional on video input. The --no-show option remains
available. These options affect data access and command-line use; the SVD,
truncation, reorthogonalization, error calculations, and plotting algorithms
use the same implementation.

The included uint8 data matrix is derived from the same recording and has
shape (5184, 92). I retain the original full video locally. The prepared data
allows the results to be reproduced without distributing that full video.
